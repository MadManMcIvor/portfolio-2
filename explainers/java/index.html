    Modern Java: a quick reference

    Java as it's written today: records, sealed types, pattern matching, virtual threads, and void main() with no class around it. This reference assumes you can already program and focuses on how Java does things and why. Where the difference is instructive, it shows the equivalent in Python, JavaScript, TypeScript or Go.

    Version this reflects: Java SE 25, the current long-term support (LTS) release, which is what most teams should target. Notes also cover JDK 27, the latest feature release (GA 15 September 2026), whose preview features are marked Preview. Checked October 2026.

    Philosophy, trade-offs, and where it's used

    Java optimizes for large teams maintaining large codebases for a long time. It chooses explicitness over brevity, a stable runtime over language novelty, and backward compatibility over almost everything. The JVM is the real product; the language is a careful, slow-moving front end to it.

    The trade-offs, stated plainly

    Compatibility is sacred. Bytecode compiled for Java 8 still runs on JDK 27. That's why features arrive slowly (and through multi-round previews) and why old APIs like java.util.Date are deprecated in spirit but never removed. Python broke compatibility once (2 → 3) and it cost a decade; Java decided never to do that.

    Static, nominal typing. Types are declared by name: a class implements an interface only if it says so. That's the opposite of Go and TypeScript, where structure decides compatibility. Nominal typing makes large refactors safe and IDE navigation exact, at the cost of ceremony.

    A managed runtime that gets faster while running. Code starts interpreted, then the JIT compiler profiles hot paths and compiles them to optimized machine code. Long-running servers get very fast; short-lived CLIs pay a startup cost (GraalVM native images and the newer AOT cache work address that).

    Garbage collected, with tunable collectors. You never free memory, and you choose a collector to trade throughput against pause time. G1 is the default everywhere as of JDK 27.

    Slow language, fast platform. The six-month release train ships something every March and September. Features land as preview first (opt-in with --enable-preview) and only become permanent after feedback.

    From source to machine code

    Step through what happens between App.java and your CPU. This is the main thing Java does that Python, JS and Go don't do the same way.

    Compared with other languages

    vs Python / JavaScript: both are dynamically typed and interpreted (with JITs in V8 and PyPy). Java checks types before running and compiles to a portable bytecode first. You give up REPL-driven looseness (though jshell exists) and gain refactoring safety and predictable performance.

    vs TypeScript: TS types are erased and advisory; the runtime is still JS. Java types are enforced by the compiler and checked by the JVM (a bad cast throws at runtime). Generics, though, are erased in both, which surprises people.

    vs Go: closest philosophically (boring on purpose, built for teams), but Go compiles ahead-of-time to a static binary with a tiny runtime, while Java ships bytecode to a big adaptive VM. Go favors structural interfaces and explicit error values; Java favors nominal types and exceptions.

    Where it's used in industry

    Back-end services at banks, insurers, airlines, retailers and telecoms (usually Spring Boot, increasingly Quarkus or Micronaut). Big-data infrastructure: Kafka, Spark, Flink, Cassandra, Elasticsearch and Hadoop are JVM projects. Android (alongside Kotlin, which runs on the same ecosystem). Trading systems that tune the JVM for low latency. Developer tools: IntelliJ, Gradle, Jenkins, Bazel. Minecraft. If a company has a large back office, Java is probably in it.

    Reach for it when

    • A service will live for years and be maintained by people who didn't write it.
    • You need high sustained throughput and a mature profiling and monitoring story.
    • You're in the JVM data ecosystem (Kafka, Spark, Flink) already.
    • You want lots of blocking-style concurrency without async/await (virtual threads).

    Watch out for

    • Startup time and memory footprint for tiny CLIs or scale-to-zero functions; consider GraalVM native image or Go.
    • Framework magic (annotations, reflection, proxies) hiding what actually runs.
    • Old tutorials: lots of top search results still teach Java 8 idioms.

    Toolchain: install, run, build, test, debug

    You install a JDK (compiler, runtime, and tools), then let a build tool (Maven or Gradle) handle compiling, dependencies, testing and packaging. Unlike Go, none of the formatter, linter or test runner ships with the language; you pick them and wire them into the build.

    Install a JDK

    "Java" has many builds of the same OpenJDK source: Eclipse Temurin, Amazon Corretto, Azul Zulu, Oracle's own, and others. Temurin is a safe free default. Use a version manager, similar to pyenv, nvm or goenv:

    Terminal

    Other routes: winget or the Adoptium installer on Windows, Homebrew casks on macOS, or mise/asdf if you already use them for Node and Go. For a project, also commit a .sdkmanrc (or .tool-versions) so everyone uses the same JDK.

    Reach for it when

    • java File.java: scripts, experiments, quick checks.
    • Maven: most services and libraries; it's the most common choice in industry.
    • Gradle: Android, big multi-module builds, or when you need custom build logic.

    Syntax essentials

    C-family syntax: braces, semicolons, for/while, and every statement lives inside a method, which lives inside a type. Modern Java removed much of the old noise: var for locals, text blocks, switch expressions, records, and enhanced instanceof.

    Variables and constants

    A local variable is declared with its type (int count = 3;) or with var, which infers the type from the right-hand side but keeps it fixed. Adding final makes a variable assign-once, similar to const in JavaScript: the name can't be rebound, but an object it points to can still be mutated. A true constant is a static final field on a class, named in UPPER_SNAKE_CASE by convention (static final int MAX_RETRIES = 3;). There's no separate const keyword; it's reserved but unused.

    Constants.java
    public final class Limits {
    public static final int MAX_RETRIES = 3;                // class-level constant
    public static final Duration TIMEOUT = Duration.ofSeconds(10);
    private Limits() {}                                     // no instances
}

void example() {
    int attempts = 0;                // mutable local
    final String region = "eu-west"; // assign once
    var started = Instant.now();     // inferred as Instant, still statically typed
    attempts++;                      // fine
    // region = "us-east";           // compile error: cannot assign a value to final variable
}

    What's different: no destructuring in a for-each over a map (you get a Map.Entry), though record patterns get you destructuring elsewhere. No collection literals; List.of/Map.of are the substitutes. var works only for local variables, never fields, parameters or return types, because Java wants signatures to be readable without inference. No default or named arguments, which is why you see overloads and builders.

    Equality: == compares primitive values and object identity. Use .equals() for value equality. Python's ==/is split maps onto Java's equals/==, flipped.

    Reach for it when

    • var: when the right-hand side makes the type obvious (var users = new ArrayList<User>()).
    • Switch expressions: any time you'd write an if/else chain that assigns one variable.
    • Text blocks: SQL, JSON, HTML, multi-line test fixtures.

    Watch out for

    • Old-style case X: with colons still falls through. Prefer arrows.
    • var x = 1; infers int, var list = new ArrayList<>(); infers ArrayList<Object>. Give the diamond a type when using var.
    • "a" == "a" may be true (interning) and then false in production. Always equals.

    The type system

    Two worlds: eight primitives (int, long, double, boolean, char, byte, short, float) that hold raw values, and reference types (everything else) that point at objects on the heap. Generics only work with reference types, so each primitive has a wrapper class (Integer, Long…) and Java converts between them automatically, which is called boxing.

    Boxing makes == lie

    Java caches Integer objects for -128 to 127. Inside that range, two boxed values are the same object; outside it, they're different objects with the same value. Drag the slider.

    Generics are erased

    Generic type parameters exist at compile time and disappear in bytecode, which is the same deal TypeScript gives you. At runtime a List<String> is just a List. Go, by contrast, generates specialized code per type set, so its generics survive.

    Algebraic data types: records + sealed interfaces

    This is the biggest modern change. A record is an immutable data carrier with equals, hashCode and toString generated (Python's frozen dataclass, a TS readonly type, a Go struct with value equality). A sealed interface lists exactly which types implement it, so a switch over it can be checked for exhaustiveness, just like a TypeScript discriminated union.

    Java
    sealed interface Shape permits Circle, Rect {}
record Circle(double r) implements Shape {}
record Rect(double w, double h) implements Shape {
    Rect {                                   // compact constructor: validate
        if (w < 0 || h < 0) throw new IllegalArgumentException("negative side");
    }
}

static double area(Shape s) {
    return switch (s) {                      // exhaustive: no default needed
        case Circle(double r) -> Math.PI * r * r;            // record pattern
        case Rect(double w, double h) when w == h -> w * w;  // guard
        case Rect(var w, var h) -> w * h;
    };
}
    TypeScript
    type Shape =
  | { kind: "circle"; r: number }
  | { kind: "rect"; w: number; h: number };

function area(s: Shape): number {
  switch (s.kind) {
    case "circle": return Math.PI * s.r ** 2;
    case "rect":   return s.w * s.h;
  }   // exhaustive thanks to the union + return type
}
    Python
    from dataclasses import dataclass

@dataclass(frozen=True)
class Circle: r: float
@dataclass(frozen=True)
class Rect: w: float; h: float

def area(s: Circle | Rect) -> float:
    match s:
        case Circle(r=r): return 3.14159 * r * r
        case Rect(w=w, h=h): return w * h
    Go
    type Shape interface{ isShape() }
type Circle struct{ R float64 }
type Rect struct{ W, H float64 }
func (Circle) isShape() {}
func (Rect) isShape()   {}

func Area(s Shape) float64 {
    switch v := s.(type) {   // not checked for exhaustiveness
    case Circle: return math.Pi * v.R * v.R
    case Rect:   return v.W * v.H
    }
    panic("unreachable")
}

    What's different: Java's union is nominal (you name the permitted types) where TypeScript's is structural (any object with kind: "circle" fits). Exhaustiveness is enforced by javac; add a third shape and every switch without a default stops compiling, which is the point. Go has no sealed types, so its type switches can't be checked.

    Null

    Every reference type can be null, and the type system won't tell you which ones are. There's no ?. or ??. The tools you have: Optional<T> for return values that may be absent, Objects.requireNonNull at boundaries, and JSpecify + NullAway for compile-time checking (closest to TypeScript's strict null checks). Value classes with null-restricted types are in the works through Project Valhalla (value objects are targeted as a preview for JDK 28) but aren't usable yet.

    Reach for it when

    • Records for DTOs, events, results, map keys, and anything you'd make a dataclass.
    • Sealed interfaces + switch for state machines, ASTs, API results (success/failure variants).
    • Primitives (int, long) in hot loops and large arrays; boxes only where generics force them.

    Watch out for

    • == on Integer, Long, String. Use equals.
    • Unboxing a null Integer throws NullPointerException, e.g. int n = map.get("missing");.
    • int overflow wraps silently (Python ints don't). Use long, Math.addExact, or BigInteger.
    • Records are shallowly immutable: a List field can still be mutated unless you copy it with List.copyOf.

    Collections and data structures

    Collections are a hierarchy of interfaces (List, Set, Map, Deque) with several implementations each. You declare variables by the interface and choose the implementation for its performance and ordering. Streams sit on top for map/filter/reduce pipelines.

    What's different: Java streams are lazy and single-use, like a Python generator, not like a JS array whose .map runs immediately. Nothing runs until a terminal operation (toList, collect, forEach, count). Collections and streams are separate: you call .stream() to get into pipeline world and .toList() to get out.

    Mutability is a property of the instance, not the type. A List might be mutable (ArrayList) or not (List.of), and you only find out when add throws UnsupportedOperationException. TypeScript's ReadonlyArray catches this at compile time; Java doesn't.

    Reach for it when

    • ArrayList and HashMap by default; you'll rarely need anything else.
    • LinkedHashMap when insertion order matters (it's what Python's dict and JS's Map give you for free).
    • Streams for transform-and-collect; a plain loop when you need early exit, checked exceptions, or index arithmetic.
    • EnumMap/EnumSet for enum keys: compact and fast.

    Watch out for

    • HashMap iteration order is unspecified and changes between runs and versions.
    • Removing from a list inside a for-each throws ConcurrentModificationException. Use removeIf.
    • LinkedList is almost never faster than ArrayList or ArrayDeque.
    • List.of(...) and Map.of(...) reject null elements and duplicate keys.
    • Mutable objects as HashMap keys: change a field used in hashCode and the entry is lost. Use records.

    Functions, closures, and generics

    Java has no free-standing functions; it has methods on types. A lambda is shorthand for an object implementing a functional interface, meaning an interface with exactly one abstract method. So x -> x * 2 has no type of its own; it becomes whatever interface the context expects, such as Function<Integer,Integer> or IntUnaryOperator.

    Lambdas, method references, and the standard shapes

    Functions.java

    Why checked exceptions exist, and why people avoid them now: they were designed to make failure modes visible in signatures, which is the same goal as Go's error return. In practice they leak implementation details up the stack (why does UserService declare SQLException?) and they don't compose with lambdas.     Reach for it when

    • try-with-resources for anything AutoCloseable: files, sockets, JDBC connections, executors, HTTP clients.
    • IllegalArgumentException for bad inputs, IllegalStateException for "called at the wrong time", UnsupportedOperationException for "not implemented".
    • Sealed result types when failure is a normal branch, such as validation or parsing user input.

    • catch (Exception e) {}: silent swallowing. At minimum log it, or rethrow wrapped.
    • Losing the cause: throw new X(e.getMessage()) drops the original stack trace. Pass e.
    • Catching InterruptedException and continuing breaks cancellation. Re-set the interrupt flag.
    • Exceptions for control flow in hot paths: building a stack trace is expensive.

    equals, hashCode, and why records exist

    A regular class inherits identity equality from Object. If you want value equality you must override equals and hashCode together, consistently, or HashMap and HashSet break in confusing ways. Records generate both from their components, which is the main reason to prefer them for data.

    Reach for it when

    • Interfaces + composition for behavior; constructor injection for dependencies.
    • Records for data, sealed interfaces for "one of these variants".

    • Deep inheritance trees and "BaseAbstractManager" classes. Favor composition.
    • Calling overridable methods from a constructor: the subclass runs before it's initialized.

    Concurrency

    Java uses real threads with shared memory, and since Java 21 it has virtual threads: lightweight threads the JVM schedules onto a few OS threads, like goroutines. You write plain blocking code (no async/await), and when a virtual thread blocks on I/O the JVM parks it and runs another one on the same OS thread.

    Why virtual threads help I/O-heavy work

    12 requests, each doing 1 tick of CPU, 4 ticks waiting on the network, then 1 more tick of CPU. Four OS threads either way. Switch modes, then step or play.

    Reach for it when

    • Virtual threads for request handling, fan-out HTTP/DB calls, anything that mostly waits.
    • A bounded platform-thread pool (Executors.newFixedThreadPool(cores)) or parallel streams for CPU-bound work.

    • ThreadLocal caches multiply with millions of virtual threads; prefer ScopedValue.
    • Since Java 24, synchronized no longer pins a virtual thread to its carrier, but native calls still can. On 21–23, prefer ReentrantLock around blocking I/O.
    • HashMap, ArrayList and SimpleDateFormat are not thread-safe.
    • Parallel streams share one global pool; don't do blocking I/O inside them.

    • finalize() is deprecated for removal; use try-with-resources or Cleaner.
    • A reassigned parameter doesn't change the caller's variable, but mutating the object it points to does.

import java.net.URI;
import java.time.Duration;

/// The outcome of checking one URL. Sealed: these three are the only possibilities,
/// so every switch over a CheckResult is checked for exhaustiveness.
public sealed interface CheckResult {
    URI uri();

    record Up(URI uri, int status, Duration took) implements CheckResult {}
    record Down(URI uri, int status, Duration took) implements CheckResult {}
    record Failed(URI uri, String reason) implements CheckResult {}
}

    package dev.example.pulse;

import java.io.IOException;
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.time.Duration;

final class HttpProbe implements Probe {
    private final HttpClient client = HttpClient.newBuilder()
            .connectTimeout(Duration.ofSeconds(5))
            .followRedirects(HttpClient.Redirect.NORMAL)
            .build();                       // thread-safe; share one per app

    @Override
    public int status(URI uri) throws IOException, InterruptedException {
        var request = HttpRequest.newBuilder(uri)
                .method("HEAD", HttpRequest.BodyPublishers.noBody())
                .timeout(Duration.ofSeconds(10))
                .build();
        return client.send(request, HttpResponse.BodyHandlers.discarding()).statusCode();
    }
}
    src/main/java/dev/example/pulse/Checker.java
    package dev.example.pulse;

import dev.example.pulse.CheckResult.Down;
import dev.example.pulse.CheckResult.Failed;
import dev.example.pulse.CheckResult.Up;

import java.io.IOException;
import java.net.URI;
import java.time.Duration;
import java.util.List;
import java.util.Objects;
import java.util.concurrent.ExecutionException;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;

final class Checker {
    private final Probe probe;

    Checker(Probe probe) {                  // constructor injection
        this.probe = Objects.requireNonNull(probe);
    }

    /// Checks every target concurrently, one virtual thread each.
    /// Results come back in the same order as the input.
    List<CheckResult> checkAll(List<URI> targets) {
        try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
            List<Future<CheckResult>> futures = targets.stream()
                    .map(uri -> executor.submit(() -> check(uri)))
                    .toList();              // submit everything first...
            return futures.stream()
                    .map(Checker::await)    // ...then collect, in order
                    .toList();
        }                                   // close() waits for any stragglers
    }

    CheckResult check(URI uri) {            // package-private so tests can call it
        long start = System.nanoTime();
        try {
            int status = probe.status(uri);
            var took = Duration.ofNanos(System.nanoTime() - start);
            return status < 400 ? new Up(uri, status, took) : new Down(uri, status, took);
        } catch (IOException e) {
            return new Failed(uri, e.getClass().getSimpleName() + ": " + e.getMessage());
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();  // keep the cancellation signal
            return new Failed(uri, "interrupted");
        }
    }

    private static CheckResult await(Future<CheckResult> future) {
        try {
            return future.get();
        } catch (ExecutionException e) {        // check() threw something unexpected
            throw new IllegalStateException("check crashed", e.getCause());
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new IllegalStateException("interrupted while waiting", e);
        }
    }
}
    src/main/java/dev/example/pulse/Report.java
    package dev.example.pulse;

import dev.example.pulse.CheckResult.Down;
import dev.example.pulse.CheckResult.Failed;
import dev.example.pulse.CheckResult.Up;

import java.util.List;
import java.util.Map;
import java.util.TreeMap;
import java.util.stream.Collectors;

record Report(List<CheckResult> results) {
    Report {
        results = List.copyOf(results);     // defensive copy: records are only shallowly immutable
    }

    boolean allUp() {
        return results.stream().allMatch(r -> r instanceof Up);
    }

    String render() {
        var out = new StringBuilder();
        for (CheckResult r : results) {
            out.append(switch (r) {         // exhaustive over the sealed interface
                case Up(var uri, var status, var took) ->
                        "UP    %d %5d ms  %s".formatted(status, took.toMillis(), uri);
                case Down(var uri, var status, var took) ->
                        "DOWN  %d %5d ms  %s".formatted(status, took.toMillis(), uri);
                case Failed(var uri, var reason) ->
                        "FAIL  ---          %s  (%s)".formatted(uri, reason);
            }).append('\n');
        }
        Map<String, Long> counts = results.stream()
                .collect(Collectors.groupingBy(Report::label, TreeMap::new, Collectors.counting()));
        return out.append("summary: ").append(counts).append('\n').toString();
    }

    private static String label(CheckResult r) {
        return switch (r) {
            case Up _ -> "up";              // unnamed pattern: match the type, ignore the value
            case Down _ -> "down";
            case Failed _ -> "failed";
        };
    }
}
    src/main/java/dev/example/pulse/App.java
    package dev.example.pulse;

import java.io.IOException;
import java.net.URI;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.List;

public final class App {
    private App() {}

    public static void main(String[] args) throws IOException {
        List<URI> targets = args.length > 0 ? readTargets(Path.of(args[0])) : defaults();
        var checker = new Checker(new HttpProbe());
        var report = new Report(checker.checkAll(targets));
        System.out.print(report.render());
        System.exit(report.allUp() ? 0 : 1);      // CI-friendly exit code
    }

    static List<URI> readTargets(Path file) throws IOException {
        return Files.readAllLines(file).stream()
                .map(String::strip)
                .filter(line -> !line.isEmpty() && !line.startsWith("#"))
                .map(URI::create)
                .toList();
    }

    private static List<URI> defaults() {
        return List.of(URI.create("https://openjdk.org"), URI.create("https://example.com"));
    }
}

    How it compares in other languages

    In Go this would be a []Result filled by goroutines and a sync.WaitGroup, with Result as an interface you can't make exhaustive. Java's sealed interface gives you the exhaustive switch; the virtual-thread executor plays the role of WaitGroup when it closes.

    In TypeScript you'd write await Promise.all(urls.map(check)) and a discriminated union. Same shape, but Java's check() is ordinary blocking code with no async, and it runs on multiple cores.

    In Python it'd be asyncio.gather with httpx, or a ThreadPoolExecutor. The Java version is closest to the thread-pool approach, minus the pool-size tuning and the GIL.

    Ways to extend it (good practice)

    Add a --concurrency N flag and cap in-flight requests with a Semaphore. Parse arguments with picocli. Emit JSON with Jackson (records serialize out of the box). Retry Failed results once with backoff. Rewrite checkAll with StructuredTaskScope under --enable-preview and compare. Package it as a native binary with GraalVM and compare startup time.

    Reach for this shape when

    • Any fan-out job: health checks, crawlers, batch API calls, parallel file processing.
    • You want a testable seam: a one-method interface that a lambda can fake.

    Watch out for

    • Thousands of URLs at once can overwhelm a single host; cap concurrency per host.
    • System.exit in library code; keep it in main only.
