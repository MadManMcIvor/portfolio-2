Philosophy, design trade-offs, and where it's used


Python spends machine time to save human time. It is dynamically typed but strongly typed, interpreted from bytecode, and shipped with a large standard library, so the shortest readable program is usually also the idiomatic one.


The design values that explain most of the language's choices are short enough to remember: readability counts, explicit beats implicit, and there should be one obvious way to do something. Run python -c "import this" to see the full list. The language evolves through PEPs (Python Enhancement Proposals) debated in public, which is why features land slowly but rarely get removed.



The trade-offs

Duck typing is the core idea


Python asks "does it have the method I need?" rather than "is it declared to be this type?". A function that calls .read() accepts files, sockets, buffers and test fakes alike, and typing.Protocol lets a type checker verify that shape ahead of time.









Why it differsPython checks shape at the moment of the call. Go and TS check shape at compile time; Java checks declared names. Python's typing.Protocol gives you the Go/TS-style compile-time check as an opt-in.

Toolchain: install, run, layout, packages, quality, debugging


The modern default is one tool, uv, for interpreters, virtual environments, dependencies and running commands, plus Ruff for formatting and linting, pytest for tests, and a type checker. All configuration lives in pyproject.toml.


Python's packaging history is messy (pip, virtualenv, pipenv, Poetry, conda), but standards like pyproject.toml let new tools interoperate. uv, from Astral, replaces pip, pip-tools, virtualenv and pyenv with a single fast binary, and it is what this guide uses. The key mental model: each project gets its own .venv directory holding an interpreter link and installed packages, isolated from every other project and from the system Python.










Why it differsGo ships one official tool; Python's tools are separate projects that agree on file formats. That's why the commands look similar to npm: a manifest (pyproject.toml ≈ package.json), a lockfile (uv.lock ≈ package-lock.json), and a per-project environment.





Project layout


Prefer the src/ layout. Putting the package under src/ means tests import the installed package, not whatever happens to be in the current directory, which catches packaging mistakes early.

    Syntax essentials and the type system
    

    Indentation is syntax, everything is an object, and variables are names bound to objects rather than typed slots. Types are strong (no silent coercion) but checked at runtime; annotations are documentation that tools verify, not something the interpreter enforces.
    


    The essentials in one screen
    



    Variables, constants, and declarations
    

    Python has no declaration keyword. A name comes into existence the first time it's assigned, and it can later be rebound to a value of any type: names aren't typed, values are. There's no let, const or var, and no block scope, so a name assigned anywhere in a function is local to the whole function.
    

    There's also no runtime constant. By convention, module-level names in UPPER_SNAKE_CASE are constants and nobody reassigns them; annotating one with Final makes a type checker enforce that. Final stops rebinding, not mutation, so for data that must not change use an immutable type: tuple, frozenset, frozendict 3.15+ or a frozen dataclass.
    

    






    Why it differsA Python variable is a label attached to an object, so there's nothing to declare and nothing for the runtime to freeze. JS const and Java final fix the binding, and Go const is a compile-time value. Final matches the first meaning, but only when a type checker runs.
    

    


    Numbers
    

    






    Why it differsPython picked mathematical consistency over hardware speed: arbitrary-precision ints, and floor division paired with a modulo that keeps (a // b) * b + a % b == a true for negatives. Porting integer code from Java or Go? Check every /, % and rounding call.
    

    


    Truthiness
    

    Any object can stand in a condition. Empty containers, zero, None and the empty string are false; nearly everything else is true. Classes can control this with __bool__ or __len__. (JavaScript has the same idea with different answers: there, [] and {} are truthy.)

    The type system
    

    Annotations are attached to functions and classes and read by tools. At runtime, def f(x: int) happily accepts a string. The system is gradual (unannotated code is treated as Any), nominal for ordinary classes, structural when you use Protocol, and fully erased at runtime, much like TypeScript's. Since 3.14, annotations are evaluated lazily, so you can reference a class before it's defined without quoting it.
    



    






    Why it differsPython added typing 25 years into its life, so it had to be optional and erasable to avoid breaking existing code, exactly the constraint TypeScript had with JavaScript. The practical consequence: run the type checker in CI, or the annotations are just comments.
    

    


    None, and checking for it
    

    None is a singleton, so compare with is None, not ==. There's no undefined: a missing dict key raises KeyError and a missing attribute raises AttributeError. There are no zero values either: a field you forgot to set doesn't quietly become 0 or "" as it would in Go. Type checkers narrow X | None after an if x is None: return, much like TS narrowing.
    

    When None is itself a valid value and you need a distinct "not provided" marker, 3.15 adds a sentinel builtin 3.15+ for exactly that, replacing the old _MISSING = object() trick with something that has a readable repr and works in type expressions.
    


    

    Reach for it when
      

    • match: destructuring tuples, dicts, dataclasses or command shapes; not for a three-way if.
      • 

    • Annotations: every public function and class; let inference handle locals.
      • 

    • Literal and TypedDict: typing JSON and config without writing classes.
      • 

    • Protocol: describing what a function needs from its argument.
      • 

    

    Watch out for
      

    • -7 // 2 == -4 and round(2.5) == 2 when porting numeric code.
      • 

    • An empty list is falsy, so if items: treats [] and None the same; use is None when that distinction matters.
      • 

    • match capture patterns: case RED: binds a new variable named RED. Use dotted names (case Color.RED:) to compare against constants.
      • 

    • Variables declared inside if and for blocks stay in scope afterwards: there's no block scope.
      • 

    

    

    

    



    

    Collections and standard data structures
    

    Four built-ins cover most needs: list (dynamic array), tuple (immutable sequence), dict (insertion-ordered hash map) and set. The collections, heapq and bisect modules fill the gaps, and comprehensions are the idiomatic way to build all of them.
    


    
  
    Which structure do I want?
    
  
    Pick what you mostly do with the data.
    
  
    
  
    
  
    

    




    






    Why it differsPython's dict became ordered as a side effect of a compact-hash-table optimisation in 3.6, and the order was then promised by the language. List slicing copies because Python lists hold references, and a copy of references is cheap and safe; Go slices are views over arrays, so sharing is the cheap path there.

    Reach for it when
      

    • tuple for fixed-size heterogeneous records you'll unpack; list for homogeneous, growable sequences.
      • 

    • dict as the default record for data at the edges (JSON); a dataclass once it has behaviour or many call sites.
      • 

    • Counter, defaultdict, deque before writing the equivalent by hand.
      • 

    • Generator expressions when you only iterate once, especially inside sum(), any(), max().
      • 

    

    Watch out for
      

    • [[0] * 3] * 3 creates three references to the same inner list.
      • 

    • Mutating a list or dict while iterating over it. Iterate over a copy or build a new one.
      • 

    • list.sort() returns None; sorted() returns a new list.
      • 

    • {1: "a", True: "b"} has one key, because 1 == True and they hash the same.
      • 

    • A generator can be consumed only once; a second loop sees nothing.
      • 

    

    

    

    


    

    Functions, closures, and generics
    

    Functions are ordinary objects you can pass, return and decorate. Parameters are unusually expressive (positional-only, keyword-only, defaults, variadics), closures capture variables rather than values, and generics exist only for the type checker.
    


    Parameter kinds
    



    






    Why it differsPython has keyword arguments in the call syntax itself, so the options-object, overload and builder patterns are mostly unnecessary. Make boolean and tuning parameters keyword-only (after *) so call sites stay readable.
    

    


    Closures capture variables, late
    

    A nested function keeps a reference to the variable cell in its enclosing scope, not a snapshot of its value. Python also has no block scope, so a loop variable is one variable that changes each iteration, which is the setup for a classic surprise.

    Decorators
    

    A decorator is a function that takes a function and returns a replacement, applied at definition time. Despite the @ syntax it isn't metadata like a Java annotation; it's ordinary code that runs once, when the def executes. @functools.cache, @property, @dataclass and framework routes like @app.get("/") are all decorators.
    



    Generators: lazy sequences with yield
    


    A generator function pauses at each yield and resumes when the consumer asks for the next value, so memory use stays flat however large the input. yield from other() delegates to another generator.
    


    Generics
    

    






    Why it differsPython's square brackets look like Go's, but the semantics are TypeScript's: generics are erased and exist only for the checker. At runtime, Stack[int]() and Stack[str]() are the same class. The pre-3.12 spelling with TypeVar("T") still works and is what you'll see in older code.
    

    


    

    Reach for it when
      

    • Keyword-only parameters for anything boolean or tunable.
      • 

    • Generators for pipelines over large or infinite data.
      • 

    • functools.cache / lru_cache for pure functions with repeated inputs.
      • 

    • functools.partial instead of a lambda that just fixes arguments.
      • 

    • Decorators for cross-cutting concerns (retry, timing, auth), not business logic.
      • 

    

    Watch out for
      

    • Mutable default arguments: def f(x, acc=[]) shares one list across every call. Default to None.
      • 

    • Lambdas are single expressions; anything longer deserves a named def.
      • 

    • Late-binding closures in loops (see above).
      • 

    • Forgetting @functools.wraps in decorators breaks introspection, docs and some frameworks.
      • 

    • Calling a generator function runs nothing until you iterate.
      • 

    

    

    

    



    

    Error handling
    

    Python uses exceptions for errors, including ordinary ones like a missing key or a bad parse. The house style is "easier to ask forgiveness than permission": try the operation and handle the failure, rather than checking every precondition first.
    


    
  
    Which blocks run?
    
  
    Pick what happens inside the try, then step through.
    
  
    
  
    
    
    
    
    
  
    

    




    






    Why it differsGo makes every error visible at the call site; Python makes the happy path uncluttered and relies on exceptions propagating until someone can handle them. raise X from exc is the equivalent of Go's %w wrapping or Java's cause argument. Python has no checked exceptions, so document what a function raises in its docstring.
    

    


    Cleanup: with and context managers
    


    The object's __enter__ runs on entry and __exit__ on the way out, with any in-flight exception passed in so it can be handled or suppressed. It fills the role of try-with-resources in Java or defer in Go.
    


    Several failures at once: exception groups
    

    When concurrent tasks fail, you may have more than one exception. ExceptionGroup bundles them and except* handles each type separately; asyncio.TaskGroup raises one of these.
    



    

    Reach for it when
      

    • A small hierarchy of your own exceptions per package, rooted in one base class.
      • 

    • raise ... from exc whenever you translate a low-level error into a domain error.
      • 

    • with for every resource: files, locks, connections, transactions, temporary directories.
      • 

    • else: on a try for code that should run only on success, without widening the try.
      • 

    

    Watch out for
      

    • Bare except: or except BaseException: they catch KeyboardInterrupt and SystemExit. Catch Exception at most.
      • 

    • Wide try blocks that accidentally catch errors from unrelated lines.
      • 

    • Swallowing errors silently. At minimum log with log.exception(...), which includes the traceback.
      • 

    • return inside finally discards the in-flight exception; 3.14 warns about it.
      • 

    • Catching asyncio.CancelledError and not re-raising it breaks cancellation.
      • 

    

    

    

    


    

    Objects and code reuse
    

    Python has classes with multiple inheritance, but idiomatic code leans on three lighter tools: dataclasses for data, protocols for structural interfaces, and the data model (dunder methods like __len__ and __eq__) for making your objects work with built-in syntax.
    




    






    Why it differsA Protocol is Go's interface model for Python: define it where it's consumed, and anything with the right methods qualifies. Use an ABC when you want Java-style explicit opt-in, shared implementation in the base class, or a runtime error for unimplemented methods.
    

    


    






    Why it differsA frozen dataclass is closest to a Java record plus a free "wither" (replace). Unlike a Go struct it's still a reference: u2 = u shares one object, which is why frozen=True matters when you pass it around.
    

    


    Inheritance and the method resolution order
    

    Python allows multiple inheritance and resolves it with a fixed linear order (C3 linearization), visible as Model.__mro__. The surprise: super() means "the next class in the instance's MRO", not "my parent", which is what makes cooperative mixins work.

      •

    Concurrency model
    

    Python gives you three tools and you choose by workload. asyncio and threads overlap waiting, which suits I/O. Processes, or the newer free-threaded build, run Python code on several cores at once, which suits CPU work. The global interpreter lock (GIL) is why that split exists.
    

    In the default CPython build, only one thread executes Python bytecode at a time; a thread releases the GIL while it waits on I/O or sleeps, and many C extensions (NumPy, hashing, compression) release it during heavy work. The free-threaded build (python3.15t) removes the GIL; it has been officially supported since 3.14, is still optional, costs some single-threaded speed and memory, and needs extensions built for it. The official 3.15 macOS installer includes it by default.
    


    
  
    Three tasks, four strategies
    
  
    Each task does some CPU work, waits on I/O, then does more CPU work. Choose a strategy and a workload, then play the timeline.

    Why it differsasyncio is the JavaScript model: one thread, explicit await points, and "colored" functions where async can call sync but not the reverse. Go and Java virtual threads let ordinary blocking code scale instead. TaskGroup is Python's errgroup: if one task fails, the others are cancelled and the errors arrive as an ExceptionGroup.
    

    




    Other pieces
    

    

    queue.Queue / asyncio.Queue
    Python's channels: producer/consumer hand-off for threads or tasks respectively.
    

    threading.Lock
    Still needed with the GIL: count += 1 is several bytecodes and can interleave. Essential on the free-threaded build.
    

    concurrent.interpreters 3.14+
    Multiple isolated interpreters in one process, each with its own GIL; InterpreterPoolExecutor wraps them. Lighter than processes, but objects aren't shared.
    

    TaskGroup.cancel() 3.15+
    Stop a task group early once you have the answer, instead of raising a dummy exception.
    

    anyio, trio
    Third-party async libraries with stricter structured-concurrency semantics; anyio runs on top of asyncio.
    

    


    

    Reach for it when
      

    • asyncio: many concurrent network calls or connections, and your libraries are async (httpx, asyncpg, FastAPI).
      • 

    • Threads: blocking libraries (requests, boto3, database drivers) and a moderate number of concurrent calls.
      • 

    • Processes: CPU-bound pure-Python work where the inputs and outputs pickle cheaply.
      • 

    • Free-threaded build: CPU-bound threads that share large in-memory state, once your dependencies support it.
      • 

    

    Watch out for
      

    • Calling a blocking function (time.sleep, requests.get) inside async def: it freezes every task.
      • 

    • Calling a coroutine without await: nothing runs (unlike a JS promise, which starts immediately).
      • 

    • Fire-and-forget asyncio.create_task without keeping a reference: the task can be garbage-collected mid-flight.
      • 

    • Assuming the GIL makes your code thread-safe; it protects the interpreter, not your invariants.
      • 

    • Process pools pickle every argument and result; large payloads can cost more than the work.
      • 

    

    

    

    


    

    Memory model: references, mutability, and garbage collection
    

    Every Python variable is a name pointing at an object on the heap, even for integers. Assignment never copies; it adds another name for the same object. Whether that matters depends entirely on whether the object is mutable.
    

    This is the same model as JavaScript objects and Java references, applied uniformly: there are no primitives with value semantics. Integers, strings and tuples behave like values only because they're immutable, so sharing them is harmless. Function arguments follow the same rule ("call by sharing"): the function gets a new name for the caller's object, so it can mutate a list it was given but can't rebind the caller's variable.
    


    
  
    Names, objects, and reference counts
    
  
    Step through the code. Arrows are references; the number on each object is its reference count.
    
  
    
    
    
    
  
    
  
    
  
    

    


    






    Why it differsGo lets you choose value or pointer semantics per type and per call. Python, like JavaScript, made everything a reference so the language could stay small and uniform; immutability is how you get value-like safety. That's why frozen=True dataclasses, tuples and the new frozendict matter more in Python than final does in Java.
    

    


    How memory is reclaimed
    

    

    Reference counting
    CPython frees an object the moment its count reaches zero. That's why files often close promptly even without with, but don't rely on it: other implementations (PyPy) and the free-threaded build behave differently.
    

    Cycle collector
    A generational collector finds groups of objects that only reference each other (a parent with a child that points back). gc.collect() forces a pass; gc.freeze() helps pre-fork servers avoid copy-on-write.
    

    Immortal objects
    Since 3.12, objects such as None, True and small ints are immortal: their counts never change, which helps multi-core and pre-fork workloads.
    

    weakref
    References that don't keep an object alive; use weakref.WeakValueDictionary for caches keyed to live objects.
    

    tracemalloc
    Standard-library allocation tracker: snapshot, diff and find what's growing.
    

    

    Compared with the JVM and Go, there's no tuning of heap sizes or GC pauses for most services; the cost instead shows up as per-object overhead. An int is a full object (28 bytes on 64-bit builds) and a list stores pointers to objects, which is why numeric work moves to NumPy arrays and why __slots__ (or slots=True on a dataclass) saves real memory when you have millions of instances.
    


    

    Reach for it when
      

    • Immutable types (tuple, frozenset, frozendict, frozen dataclasses) for anything shared across functions, threads or caches.
      • 

    • copy.deepcopy only at boundaries where you truly need isolation; it's slow.
      • 

    • slots=True for classes with many instances.
      • 

    • with for every resource, rather than trusting reference counting.
      • 

    

    Watch out for
      

    • a += [4] mutates the list in place, but a = a + [4] creates a new one; other names see the first change only.
      • 

    • is compares identity. x is 1000 may be true or false depending on caching; use == for values.
      • 

    • Shallow copies of nested structures still share the inner objects.
      • 

    • __del__ finalizers: their timing isn't guaranteed and they complicate cycles. Prefer context managers or weakref.finalize.
      • 

    

    

    

    



    

    Modules, packages, and visibility
    

    A module is a .py file; a package is a directory of modules. Importing a module runs its top-level code once and caches the result. Visibility is a naming convention, not a compiler rule.
    






    






    Why it differsPython trusts its users ("we're all consenting adults") and makes everything reachable for debugging, testing and monkeypatching. The underscore is a social contract that linters and IDEs enforce. To hide a whole subpackage, name it _internal; there's no compiler-enforced equivalent of Go's internal/.
    

    


    Lazy imports 3.15+
    

    Big applications pay for every top-level import at startup. 3.15 adds the lazy soft keyword: the import is declared at the top of the file as usual, but the module only loads when the name is first used.
    



    

    Reach for it when
      

    • Absolute imports (from shop.models import Order) in application code; relative imports inside a package's own modules.
      • 

    • __all__ plus re-exports in __init__.py to define a small, stable public API.
      • 

    • python -m package.module to run code inside a package.
      • 

    • importlib.resources.files("shop") / "data.json" for files shipped inside a package.
      • 

    • lazy import for heavy, rarely used dependencies in CLIs and serverless handlers.
      • 

    

    Watch out for
      

    • Circular imports: usually a sign two modules should be merged or a third extracted. Importing the module (import a) rather than names (from a import f) defers the lookup and often breaks the cycle.
      • 

    • from config import DEBUG copies the binding; if config.DEBUG is reassigned later you won't see it. Use config.DEBUG.
      • 

    • Naming your file random.py or json.py shadows the standard-library module.
      • 

    • Heavy work (network calls, reading config) at import time; keep top-level code to definitions.
      •

    Gotchas
    

    Predict the output, then reveal it. Where another common language behaves differently, the card notes it.
    

    


    The shared default argument
    


    Reveal
    [1, 2]
    

    Defaults are evaluated once, when def runs, and the same list is reused. Use bucket=None and create the list inside.
    

    JS and TS evaluate defaults on every call, so they'd print [2].
    


    A coroutine that never runs
    


    Reveal
    done
RuntimeWarning: coroutine 'save' was never awaited
    

    Calling an async function only creates a coroutine object. It runs when awaited or wrapped in a task.
    

    A JS promise starts executing immediately, so save() without await would still print.
    


    Negative floor division
    


    Reveal
    -4 1 -3
    

    // floors toward negative infinity and % follows the divisor's sign. int() truncates toward zero, like Java's cast.
    

    Java, Go and JS give -3 -1 for the first two.
    


    Banker's rounding
    


    Reveal
    0 2 2
    

    Ties round to the nearest even number, which avoids bias when summing. For money, use decimal.Decimal with an explicit rounding mode.
    

    JS Math.round and Java Math.round give 1 2 3.
    


    Empty list in a condition
    


    Reveal
    empty
    

    Empty containers are falsy.
    

    In JS, [] and {} are truthy. In Java and Go this wouldn't compile.
    


    Nested list multiplication
    


    Reveal
    [[1, 0, 0], [1, 0, 0], [1, 0, 0]]
    

    The outer * 3 repeats a reference to one inner list. Write [[0] * 3 for _ in range(3)].
    

    Same trap as Array(3).fill([]) in JS.
    


    Assigning to an outer variable
    


    Reveal
    UnboundLocalError: cannot access local variable 'count'...
    

    Any assignment in a function makes the name local for the whole function. Use global count (or better, return a value), or nonlocal inside nested functions.
    

    JS, Java (for fields) and Go would all happily modify the outer variable.
    


    No block scope
    


    Reveal
    2 20
    

    Loop variables and anything assigned in if/for/with blocks live in the enclosing function. (Comprehension variables, however, don't leak.)
    

    With let in JS, or in Java and Go, i would be out of scope.
    


    One-element tuples
    


    Reveal
    int tuple tuple
    

    The comma makes the tuple, not the parentheses. A stray trailing comma after an assignment silently creates a tuple.
    


    Keys that collide
    


    Reveal
    {1: 'bool'}
    

    1 == 1.0 == True and they hash equal, so they're the same key. The first key object is kept and the last value wins.
    

    A JS Map would keep three entries; JS objects would stringify to two keys.
    


    sort() returns None
    


    Reveal
    None
    

    Methods that mutate in place return None by convention. Use sorted(nums) for a new list.
    

    JS's sort() sorts in place and returns the array, which hides the difference.
    


    Importing a name, not a variable
    


    Reveal
    False
    

    from x import NAME binds a new name to the current object. Rebinding inside settings isn't seen. Use import settings and read settings.DEBUG.
    

    ES modules have live bindings, so JS would print true.
    


    A generator used twice
    


    Reveal
    6 0
    

    Generators are single-pass. Materialize with list() if you need to iterate more than once.
    

    Like a Java Stream, except Python doesn't raise; it just yields nothing.
    


    Type hints don't stop anything
    


    Reveal
    ababab
    

    Annotations aren't checked at runtime. Only a type checker in CI catches this; use Pydantic or msgspec if you need validation at a boundary.
    

    TS behaves the same after compilation; Java and Go would refuse to compile.
    


    Grouped except clauses
    


    Reveal
    caught   (on 3.14+; SyntaxError on 3.13 and earlier)
    

    Since 3.14 the comma form catches either type, but only without as. To bind the exception you still need except (ValueError, TypeError) as e:. In Python 2 the same text meant something else entirely.
    


    The default encoding changed
    


    Reveal
    utf-8   (3.15+, on every platform)
    

    Before 3.15 this used the locale encoding, often cp1252 on Windows. Code that silently depended on that now reads files differently. Passing encoding="utf-8" explicitly is still the portable choice.
    


    

    

    


    

    Standard library and ecosystem highlights
    

    "Batteries included" is still true: JSON, TOML, SQLite, HTTP, compression, dates with time zones, CLI parsing, logging and testing all ship with the interpreter. Filter the table to find a module.

    Template strings 3.14+
    

    A t"..." literal looks like an f-string but produces a Template object holding the static parts and the interpolated values separately, so a library can escape them (SQL, HTML, shell) before combining. It's the same idea as JavaScript's tagged template literals.
